- **Added**: a per-read budget. A method call that walks more rows (`--read_budget_rows`), or builds more result memory (`--read_budget_mb`), than it allows is stopped and refused with its own status, `"status": "read_too_large"` (over the binary protocol, an error starting `read too large`), instead of running until `orlyi` runs out of memory. Like `write_too_large` it is not retryable as sent. The defaults come from the memory budget: a sixteenth of it, at least 16 MiB, and one row per 256 bytes of that. `--read_budget_mb=0` turns the budget off. The TS, Python and Go clients raise `ReadTooLargeError`, `orly.ReadTooLarge` and `ErrReadTooLarge` for it; `docs/PROTOCOL.md` explains it ([#694](https://github.com/orlyatomics/orly/issues/694)).
