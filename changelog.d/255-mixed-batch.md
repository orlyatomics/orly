- **Added**: a batch can now mix methods. `try {pov} [pkg1 m1 <{...}>, pkg2 m2 <{...}>, ...];` runs calls to different packages and methods as one transaction, so several different writes (creating an entity and linking it, say) land together or not at all. It follows the same-method batch from #253: one commit, all-or-nothing (a call to an unknown package or method rejects the whole batch), and every call reads the same pre-batch snapshot. The reply is a JSON array with one result per call, and the entries may differ in type. The TS, Python and Go clients have `callMany`, `call_many` and `CallMany`. Both kinds of batch now run through one server path, and the same-method batch's reply and meta record are unchanged. A new CI smoke, `clients/smoke/run-multi-batch.sh`, covers mixed results, the all-or-nothing rule, snapshot reads and the same-method batch (#255).
