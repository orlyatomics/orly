- **Fixed**: a slave didn't keep the exactly-once table (#733), so after a failover a write sent again with the same operation id ran a second time on the promoted slave. A slave now reads each replicated write's operation id and result into its own table, as WAL recovery does. Ids from before the slave joined reached it only as synced data, so it refuses any unknown id no newer than its join plus a minute as `operation_expired`. A new `tests/failover_retry_test.sh` writes with an id on a disk-backed master, kills it, and checks that the promoted slave answers the retry with the saved result and refuses an id from before the join. Its slave runs `--mem_sim`, because a disk-backed slave crashes on join, #866 (#862).
