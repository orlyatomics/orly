- **Changed**: a single write too large ever to be merged, one with more entries than half the Update Entry pool's merge reserve, is now refused with its own status, `"status": "write_too_large"` (over the binary protocol, an error starting `write too large`), instead of a generic `"exception"`. Unlike `insufficient_memory` it is not retryable: split the batch. The TS, Python and Go clients raise `WriteTooLargeError`, `orly.WriteTooLarge` and `ErrWriteTooLarge` for it. The limit is `--update_entry_pool_size` × `--memory_reserve_pct` / 100 / 2, and shrinks with the memory budget; `docs/PROTOCOL.md` explains it ([#687](https://github.com/orlyatomics/orly/issues/687)).
