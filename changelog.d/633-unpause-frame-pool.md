- **Fixed**: `unpause {<id>};` crashed `orlyi` on every call, on any kind of POV (#633). Unpausing rejoins the POV to its parent's Tetris player, which can construct a new player, and a player took its fiber frame from the calling thread's frame pool. WS statements run on `WsRunner`, whose thread never installs one, so a debug build asserted and a release build segfaulted. Each Tetris manager now keeps a pool of its own for player frames, so a player can be constructed from any thread: `unpause`, a commit on a fast runner, or startup. A player that fails to get a frame also no longer leaves `StopAllPlayers()` waiting forever on a count it never dropped.
