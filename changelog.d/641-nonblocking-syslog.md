- **Fixed**: a stalled system log daemon can no longer freeze `orlyi`. Every log line went through glibc's `syslog()`, which holds one process-wide lock across the stderr echo and a blocking send to `/dev/log`. When journald (or rsyslog) stopped reading, the socket filled, the thread inside `syslog()` blocked in the send, and every other thread that logged blocked on the lock without printing anything, so the server stopped serving and the log just ended. `base/log.cc` now provides the syslog API itself (`openlog`, `syslog`, `vsyslog`, `setlogmask`, `closelog`) for every program that links it. No lock is held while writing. A line that finds the log socket full waits up to 50 ms for room and is then dropped from the system log, not from stderr; while the daemon stays stalled, later lines are dropped without waiting. The next line that gets through is followed by a notice of how many were dropped, and the reporting port shows the total as `Syslog Dropped` (#641).
