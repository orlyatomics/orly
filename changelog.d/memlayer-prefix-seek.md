- **Changed**: a read that matches a key pattern (a prefix, or a key with trailing frees) against a memory layer now seeks to the first entry that could match, as exact-key reads have since #257, and stops at the first entry past the pattern's run. Before, it started at the head of the layer and tested every entry, including those of other indexes, and when the layer held no match, the usual case for a small layer, it went on to the end of the index. Both bounds compare a stored key with the pattern member by member while the pattern's members are fully bound, so they skip only keys that cannot unify with it. Under ingest, where memory layers stay large, this walk was about a third of a join's time. New `memory_layer.test` cases check every pattern walk against a brute-force filter of the layer and time walks that find something and walks that find nothing.
