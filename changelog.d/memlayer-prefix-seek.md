- **Changed**: a read that matches a key pattern (a prefix or a key with frees) against a memory layer now seeks to the first entry that could match, as exact-key reads have since #257, instead of starting at the head of the layer and testing every entry, including those of other indexes. The seek compares a stored key with the pattern member by member while the pattern's members are fully bound, so it skips other indexes and the keys whose leading members order before the pattern's, and never skips one that could unify with it. Under ingest, where memory layers stay large, this walk was about a third of a join's time. A new `memory_layer.test` case checks every pattern walk against a brute-force filter of the layer.
