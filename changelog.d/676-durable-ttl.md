- **Fixed**: a slave could lose the record of a pov (or session) the master saved while they were paired, so after a failover that pov failed with `durable object doesn't exist`. The master sent each durable save's ttl as a bare seconds count, which the slave did not read back as the ttl sent (a unit test read back 281474219468880 for 600). The slave then stored the record with a garbage deadline, and its durable layer dropped it as expired at the next write or merge whenever that deadline wrapped below the current time. Which records were lost varied from run to run, which made `import_replication.test`'s `SlaveInventoryKeepsPovShape` (#676) fail intermittently on master in debug and release builds. The ttl now travels as a Sabot duration, as a repo's ttl already did, and the slave decodes durable saves through one function, `TReplicationStreamer::ForEachDurable`, which the new `orly/indy/replication.test` checks against the encoder.
