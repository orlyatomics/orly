- **Fixed**: a safe repo's disk use no longer grows with every write ever made. Its disk merges kept every version of every key, and every update-index entry, forever, so overwriting the same keys eventually filled the disk and left the server refusing writes (#590). The global POV's disk merges now drop superseded versions, using the existing tail-merge pass behind the `tail` statement. Each merge keeps every key's current version, and keeps whole any update that still holds one. Nothing else reads that history: a slave join walks a view that pins the files it started from, live replication ships transactions rather than files, and child POVs, whose updates Tetris still has to promote, are never pruned. The tail pass used to drop a `+=` key's earlier increments and its base, so after a `tail` the key could read back as its last increment alone. It now keeps that history. A merge output also records the whole sequence range of its inputs, so a merge input that a crash leaves behind is still recognised and dropped on reload. `--allow_tailing=false` turns the pruning off. Measured on native arm64 with 8 writers overwriting 100k keys on one safe shared POV for 15 minutes, with the image's default volumes. On master, the low point between discard passes climbed from 35 to about 150 MB, writes started being refused for space at about 480k, and 723 were refused in all; usage settled at 143 MB after 700k writes. With the fix, the low point stayed between 45 and 75 MB, no write was refused, and usage settled at 44 MB after 752k writes (#592).
