- **Fixed**: a safe repo reopened from disk after a restart now queues a disk merge when its files hold a mergeable pair. Disk merges were queued only when a flush, a merge or a new file changed the repo's mapping, and the mapping a reopen builds from the repo's files was not one of those, so a store that was only read after a restart kept every file it came back with (one measured store stayed at 476 layers; with the merge it settles at 5, and point-read p50 roughly halves).
