- **Fixed (memory)**: orlyi no longer holds memory it has finished with long after a read burst or a disk merge. Each runner now frees, every ten seconds, the pooled file walkers that no read needed since the last time, instead of keeping as many as were ever out at once until the file merged away; and after each disk merge or walker trim, tcmalloc's free page heap beyond 128 MiB goes back to the kernel, 64 MiB at a time so that other threads are not kept off the allocator's page heap for long. With a 6 GiB budget, after a read-heavy benchmark of 1 to 256 concurrent sessions over a freshly ingested store and five idle minutes, RSS was 6.9 to 7.2 GiB in three runs against 14.1 to 14.5 GiB before, with read throughput unchanged. RSS is still above the budget, and peak RSS while the reads run is about twice it ([#988](https://github.com/orlyatomics/orly/issues/988)).
