- **Fixed**: a Tetris pop's completion no longer lands on a repo that has gone, and a repo is no longer discarded while one of its pops is still waiting to complete. A pop from a child into the safe root completes, releasing the update in the child, only once the root has written it to disk. Two things went wrong in between. A child's memory merge decided whether to drop the repo's self-pin by looking only at the layers it had merged, so a write that landed while the merge ran was missed, and an expired ttl-0 pov could be discarded with that write's pop still pending. The completion then opened the repo with `ForceOpenRepo`, which for a missing id builds an empty repo: in debug this asserted `seq_num < NextUpdate` in `TRepo::ReleaseUpdate`, and in release it left an empty repo under the expired pov's id. The merge now counts the current memory layer under the repo's data lock before dropping the pin, and the completion only touches a live repo, doing nothing for one that is gone (#665).
