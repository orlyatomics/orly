- **Added**: a WebSocket connection can keep several statements in flight. A message of the form `{"id": 17, "stmt": "...", "read": true}` is answered with the same `id`; reads run alongside other reads and are answered as they finish, while anything else waits for the statements before it and holds back the ones after. Bare statements behave exactly as before. A per-connection write queue sends one reply at a time, and `--ws_pipeline_depth` (default 16, 1 turns it off) is how many statements a connection may have sent without an answer before the server stops reading it. The clients do not take it yet (#1033).
