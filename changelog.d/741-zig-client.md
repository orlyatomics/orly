- **Added**: a Zig client, `clients/zig`, for Zig 0.17.0 and newer. It speaks the WebSocket + JSON protocol like the Go, Python and TypeScript clients: connect with retry and backoff, the #710 token (from the options or `ORLY_AUTH_TOKEN` / `ORLY_AUTH_TOKEN_FILE`), sessions, `install`, `newPov` for every safe/fast and shared/private flavour with an optional parent, `call`, `callBatch`, `callMany`, `pause`, `unpause`, and a `pages` helper for keyset paging. Each refusal status (`insufficient_memory`, `insufficient_storage`, `write_too_large`, `read_too_large`, `unauthorized`, `remote_compile_disabled`) is its own error, with the raw reply kept as `detail()`. Zig values become orlyscript literals at compile time, memory is explicit, and a call allocates only when a statement or reply outgrows the buffers the client reuses. Unit tests run with `zig build test`, and a new CI smoke, `clients/smoke/run-zig.sh`, runs the client against a live `orlyi`: the new-POV matrix, pause and unpause, mixed and failing batches, paging, and the auth refusals (with a control against a server that has no token). Zig's package manager cannot fetch a subdirectory by URL, so the client is used by path; see `clients/zig/README.md`. `clients/smoke/multi.orly` gains a `page` method for the paging smoke (#741).
