- **Changed (performance)**: a point read of a fully bound key skips the disk layers that cannot hold it. Each data file written, merged or folded by this process now keeps an in-memory blocked Bloom filter (10 bits a key, about 1% false positives) of the hashes of its keys in each index, made from the hashes the writer already computes for the file's hash index. `TRepo::TPresentWalker` tests it before building a layer's walker, so with hundreds of disk layers a point read opens only the few that may hold the key instead of probing every file's on-disk hash index. Range reads, keys with free members and files opened from disk (a restart, an import, a synced file) are read as before. Nothing on disk changes. The filters' total size is logged at INFO each time it crosses a 64 MB step.
