- **Fixed**: a merge no longer runs on a repo that has been destroyed. The merge runners took a repo off the merge queue as a raw pointer, with nothing keeping it alive. A ttl-0 pov's repo is destroyed as soon as its last pin goes, and for a fast child that happens when Tetris releases its last update, so a merge could be left running on freed memory. In debug builds this showed up as the `iter != update_remap.end()` assertion in `StepMergeMem`, or as a silent crash; in release it was undefined behaviour. The runners now pin the repo by id before merging it and skip a repo that has already gone. A repo that dies while queued now leaves the mem-merge queue under the queue's lock. This was not caused by pruning: it reproduced with `--prune_merge_history=false`. On arm64 runners, looping `import_replication`'s `PrunedJoinWithoutFileSync` failed 64 of 811 times before the fix, 25 of them with that assertion. After it, 1 of 1537 runs failed, and that one because its master never started (#614).
