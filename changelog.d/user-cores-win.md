- **Fixed (orlyi)**: a core flag the command line gave (`--fast_cores`, `--slow_cores`, `--mem_merge_cores`, `--disk_merge_cores`, `--disk_controller_cores`) did not stop the default placement of the pools it did not give: the defaults were computed over every CPU and could land on the CPUs the flag had just claimed, so `--fast_cores=2,4` left a memory merge or disk controller sharing those CPUs. Defaults for the pools not given now go around the CPUs the given ones use (over all CPUs as before when that would leave fewer than two). orlyi also logs a note at startup when a fast runner shares a physical core (hyper-thread sibling, read from `/sys/devices/system/cpu/cpu*/topology/thread_siblings_list`) with another pinned thread. The default layout itself is unchanged.
