- **Changed (performance)**: a paged read's `skip` no longer builds a key per skipped row. A sequence's `skip` stepped its key cursor once per skipped key, and each step decoded the key it landed on; key cursors now take `Skip(n)`, which steps the same merge but builds nothing for the rows it passes over, and `TSkipGenerator` asks its generator for a cursor that has already skipped. The keys, values and rows charged to the read budget are unchanged. This is the stepping half of the rank skip that [#1045](https://github.com/orlyatomics/orly/issues/1045) proposed (that issue was closed without the rank path): a skip still walks every layer, only more cheaply. `orly/indy/repo.test.cc` compares skips of none, a few keys, a stretch across files with deletes, every key and past the end against plain stepping, including under a read budget.
