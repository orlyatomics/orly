- **Added**: optional exactly-once writes (#733). A write that carries an operation id (`try ... <{.op_id: "<uuidv7>"}>;`, or the reserved closure argument `$op_id` on the binary protocol) is applied at most once however often it is sent, and a retry gets the first try's result; on a safe POV the id and result ride in the write's WAL record and the checkpoint, so that holds across a SIGKILL and restart. New statuses `operation_expired`, `operation_id_reused`, `operation_in_flight` and `outcome_too_large`; flags `--operation_retention_count` (default 4096, across all POVs), `--operation_retention_seconds` and `--operation_outcome_bytes`. The Python, TypeScript, Go and MCP clients take an id per call and resend only when they have one (the MCP server no longer resends a call that has none). The kill campaign has a `retry` writer and a `NEGATIVE=noretry` control. A new store gets 1 MiB checkpoint slots (the slot length is recorded in the system block; an existing store keeps its one-block slots). This changes what format-1 stores and checkpoints hold, so it lands before v0.3.0.
