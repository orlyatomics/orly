- **Changed (performance)**: reading record values no longer gets more expensive per call as sessions are added. Every copy of a singleton type (`str`, `int`, and the unknown type each default-constructed or moved `Type::TType` holds) bumped one shared reference count, and turning a record into a `Var` and back copies those types many times per field, so sessions reading records on several cores spent most of their CPU moving those counts' cache lines between cores: four records per call cost ~4.2x the server CPU at 8 sessions that they cost at 1, against ~1.3x for `str` values. Singletons now hand out references that don't share ownership (the type czar owns them for as long as types exist), `Var::TObj` interns its record type once when it's built instead of on every `GetType()`, and a native record's element array is read without its per-type mutex once it exists. On a 16-core arm64 box, record reads at 8 sessions went from ~20,000 to ~53,000 calls/s and from ~280 to ~90 µs of server CPU per call; on 4-core CI runners, record reads take 5-35% less CPU per call and get 5-48% more calls/s (the most at 8 sessions on arm). A new smoke, `clients/smoke/run-record-read-scale.sh`, prints calls/s and CPU per call for `str` and record values at 1, 2, 4 and 8 sessions as METRIC lines; the aarch64 release job fails if records' CPU per call at 8 sessions is more than 1.25x its one-session cost (master: 1.4x there), and the TSan server smoke now reads records from 8 sessions at once (#798).
