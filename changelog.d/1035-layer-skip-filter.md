- **Reads skip disk layers that can't hold their key** ([#1035](https://github.com/orlyatomics/orly/issues/1035)). Each disk layer keeps a small in-memory filter over the prefix hashes its file's hash tables hold. The filter is built on first use and costs 1.5 bytes per entry; tables over 2^18 slots get none. A point read, a pattern with trailing frees, or a range whose start shares its end pattern's defined prefix now passes over a layer the filter rules out. It does so without taking a file walker or reading the file's hash table. Under sustained write ingest, which leaves many small layers, about 9 in 10 per-layer point probes in a mixed point/range read workload found nothing, and those are the probes this skips.
