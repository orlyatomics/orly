- **Fixed**: the durable manager's writer woke the merger before publishing the mapping that lists the file it had just written. A merger that lapped in that window found a generation one file short of the three it merges, went back to waiting, and nothing woke it again, so those files never merged (and their inputs were never cleaned up) until the next save. Since idle fiber runners park instead of polling (#764), the merger wakes fast enough to win that race, and `fault_injection.test`'s DurableSaveMerge PowerTorn case hung in CI, about 1 run in 8 locally. The writer now wakes the merger after the mapping update. New test: `MergerSeesTheFileItWasWokenFor` holds the writer in that window and fails without the fix (#782).
