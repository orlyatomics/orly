- **Fixed (undefined behavior, hashing)**: `Util::RotatedLeft` and `RotatedRight` shifted by the full width of the type when the count was zero or a multiple of the width (the first element of every tuple hash, `Idx * 5 == 0`), which is undefined; UBSan reported it about 1,100 times in the lang tests. A count that reduces to zero now returns the value unchanged. The result for every count the old code handled on x86 is bit-for-bit the same (there the hardware masked the shift, giving `val | val == val`), so persisted hashes are unaffected. `base/util/stl.test` checks the new code against the old results for 16, 32 and 64-bit types over every count up to three widths (#989).
