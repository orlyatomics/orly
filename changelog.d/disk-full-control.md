- **Added**: CI now runs the disk-full smoke a second time with write admission turned off (`ADMISSION=off clients/smoke/run-disk-full.sh`, which passes `--disk_reserve_mb=0 --disk_reserve_pct=0`), and requires that run to *fail* once its writers have started. If the smoke ever passes without admission, CI goes red, so a change that leaves it unable to notice missing admission can't slip through. Disk pruning (#592) is the obvious way that could happen: if overwrites stopped filling the disk, nothing would get refused.
