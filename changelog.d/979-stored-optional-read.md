- **Fixed**: a value written as an optional (`<[k]> <- x as T?`) can now be read back as `T?`. The read treated `T?` only as "unknown if the key is missing" and converted the stored value as a plain `T`, so it failed with "Unable to convert sabot to given native type" on the stored optional. This happened for any `T`, not only the recursive variants it was reported against. A stored optional is now taken as it is, known or not; a value stored as a plain `T` still reads as known, and a missing key as unknown. No stored encoding changes. New lang test `optional_stored_read.orly` (#979).
