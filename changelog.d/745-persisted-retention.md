- **Added**: persisted retention and store format version 2 (#745 stage 3). With `--retention_versions` or `--retention_seconds` on, each POV keeps a retention record (its history horizon, window samples and save points) in the durable store, so a restart keeps `oldest` where it was instead of raising it to the newest version on disk. A merge never drops a version until a record that allows it is on disk. A master ships its record to its slaves, and a slave never drops a version at or above the master's horizon, so a failover keeps every version the master promised; a slave keeps all history until its master's record arrives. The first start with a retention flag upgrades a format version 1 store to version 2, which earlier binaries refuse; a store started without the flags stays at version 1, and there is no downgrade from version 2. Save points exist as an internal API only, with no protocol surface yet.
