- **Fixed (throughput)**: `TFiberLock`, `TSafeSync`, `TSingleSem` and `TSem` now wake a waiting fiber after releasing their spin lock instead of from inside it, as `TCompletionTrigger` already did. Since idle runners park on a futex (#764), that wake is a system call, and a woken runner that shares the waker's core (the memory and disk merge runners are all pinned to the merge cores) could preempt the waker and then spin on the lock the waker still held until the kernel took its time slice back. That cost ~3 ms per wake between the memory merge runners and cut x86 pool-pressure write throughput by ~9% on average and up to 20% per shot. In a 4-core run the merge-mem runners' time inside wakes fell from ~5.2 s each to ~0.02 s (#772).
