- **Fixed**: after a restart, the file map's base images keep all their blocks. A base image of more than 818 files spans a chain of blocks, but on reopen only the first block of each image was marked used, so the rest of both chains looked free and a data file or merge could be written over them. A crash or restart before the next base image was written then failed to load the image the server had started from, and the older image could not stand in for it, so the server stopped with "File System is corrupt". On reopen, the file service now marks the chain of the image it loaded used, and the chain of the other image too when every block of it is intact, since that one is the fallback. A broken chain is left free, because its links can't be trusted. The next base image reuses those blocks in place. A chain block that a file already holds stays with the file, and that image gets fresh blocks next time. A chain whose links loop is now reported as broken instead of being followed forever (#610).
