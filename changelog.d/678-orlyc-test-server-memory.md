- **Fixed**: `orlyc` no longer needs about 600 MiB on top of the compile. The test server it stands up for a package's `test` blocks had a fixed 512 fiber frames, whose 1 MiB stacks are `mlock`ed and so all resident wherever memlock is unlimited; an in-container compile under `--memory=1g` got the container OOM-killed, `orlyi` with it. It now has 64, four times the most any lang test needs, and its peak is about 150 MiB. A package without `test` blocks gets no server at all; `orlyc` still loads the built package to check it, and prints `MM_NOTICE: No tests` in machine form. An in-container compile now needs about 400 MiB of headroom, nearly all of it `g++` (#678).
