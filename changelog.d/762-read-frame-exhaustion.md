- **Fixed (crash)**: a point read that couldn't get a fiber frame for every disk layer took `orlyi` down (`Bad Alloc in TThreadLocalPool [Orly::Indy::Fiber::TFrame]`, then `pure virtual method called`). A single-key read built each disk layer's walker on its own fiber frame, so a read needed one frame per layer (53 in the report), and when the pool ran dry part way the read unwound while the fibers it had already started were still running against it. Now a read fans out over at most 8 frames, each building every 8th layer; a frame it can't get, it builds inline instead of failing; it never takes a frame another thread has freed (those are the frames statements are waiting for); and reads together hold at most half of `--max_parallel_frames`. An error building a layer's walker on a fiber now fails the read instead of hanging it. A WebSocket statement that finds no frame free waits up to a second for one and is then refused as retryable `insufficient_memory` (it never ran), instead of failing with a bare `std::bad_alloc`. A new smoke (`clients/smoke/run-read-fanout.sh`) runs 128 readers over ~48 disk layers with 64 WebSocket threads and 200 frames: on master `orlyi` dies within a second; now every read answers (#762).
