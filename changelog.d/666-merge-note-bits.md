- **Fixed**: in release builds, a disk merge could write two copies of one key into its output, so a read of that file stopped folding a `+=` chain partway and returned a wrong value. A merge drops a value it has already written by comparing the stored bytes. Each stored value starts with a header, and six bits of that header were never set, so release builds left in them whatever the memory held before. Debug builds zero new memory, which is why every test passed there. The bits are now set to zero, and the merge leaves them out of the comparison, so files already on disk merge correctly too. Until now a merge's output was only served unfolded when it had no `+=` entries, and reads never fold those, so no released read returned a wrong value from it. CI's release job now also runs the storage and merge unit tests, because `make test` builds debug only (#666).
