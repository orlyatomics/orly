- **Fixed**: in release builds, a disk merge could write two copies of one key into its output, so a read of that file stopped folding a `+=` chain partway and returned a wrong value. A merge drops a value it has already written by comparing the stored bytes. Each stored value starts with a header, and six bits of that header were never set, so release builds left in them whatever the memory held before. Debug builds zero new memory, which is why every test passed there. The bits are now set to zero, and the merge leaves them out of the comparison, so files already on disk merge correctly too. Normally a merge's output with `+=` entries is folded before anything reads it, but after a power cut during that fold a restart could serve the unfolded output, and a release build then read its `+=` keys wrong. Files that release builds wrote before this fix can still hold the duplicate copies; #674 tracks what to do about them. CI's release job now also runs the storage and merge unit tests, because `make test` builds debug only (#666).
