- **Fixed**: reads that walked a memory layer while Tetris or a session was inserting into it followed the layer's list links with no synchronization: the entry and update lists were plain pointers written by the inserting thread and read by the walkers, so ThreadSanitizer reported a data race (`ordered_list.h:82` against the insert), and on a weakly ordered CPU such as arm64 a reader could in principle reach an entry before seeing what the writer had stored in it. `InvCon::OrderedList` now takes a link policy. The default, plain pointers, is unchanged for every other list. The memory layer's two lists use the new `TPublishedLinks`: one writer and any number of lock-free readers, where an insert fills in the new member's own links first and then publishes it with release stores (the predecessor's next link, then the successor's previous one), and every link a reader follows is an acquire load. The invariant (one writer at a time, readers never see a removal) is documented on `TPublishedLinks` and `TMemoryLayer`. A new `memory_layer.test` case walks a live layer with point, exact-point, range and update walkers while another thread inserts out of order: 115 TSan reports before, none after. It and the new published-list cases in `ordered_list.test` join the CI TSan job. The same TSan run of the read fan-out smoke also reported `Durable::TObj::OnPtrRelease`: its `assert(PtrCount)` read the count before taking the manager's lock. The assert now runs under the lock; release builds compile it out, so only debug and sanitizer builds were affected (#770).
