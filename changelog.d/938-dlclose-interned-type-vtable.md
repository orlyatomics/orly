- **Fixed**: `orlyi` could segfault in `TFuncInfo::~TFuncInfo()` inside `dlclose` at shutdown or package uninstall after a package had been upgraded from an earlier version (#938). `TInternedType::Get` was defined inline in the type headers, so a compiled package `.so` instantiated `TInternedType<...>::Get` and its `std::_Sp_counted_deleter` vtable inside the package's own address space. When version 1 of a package loaded first, it constructed interned `TType` instances whose `shared_ptr` control blocks pointed at version 1's `_Sp_counted_deleter` vtable; when version 2 loaded next, it shared those interned `TType` instances through `TypeByKey` and `dlclose`d version 1, leaving the control blocks' vtable pointers dangling in version 1's unmapped `.data.rel.ro` segment until version 2 later unloaded and released the last reference. All `TInternedType` and `TUnaryType` `Get` methods are now defined out-of-line in `orly/type/*.cc`, so interned `TType` instances and their `shared_ptr` control blocks are always constructed inside the host binary (`orlyi`). Existing packages compiled with an older `orlyc` should be recompiled so their static constructors call the out-of-line `Get` symbols instead of their own inline copies.
