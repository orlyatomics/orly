- **Fixed**: orlyi's default thread layout now follows the CPUs the process may run on, not every CPU online. Under `taskset` or a container cpuset it used the whole machine's table and pinned threads outside the mask: `taskset -c 0-11` on 16 CPUs put three of the six fast runners and a disk controller on 12-15, which were meant for something else. The table is now chosen by the size of the affinity mask and laid over the CPUs in it, so a process with every CPU gets the same layout as before, and `--fast_cores` and the other core flags still override it. The resolved layout is logged at startup as before. A new `core_layout.test` covers the table and the masked mapping.
