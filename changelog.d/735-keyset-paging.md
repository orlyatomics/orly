- **Added (language)**: keyset paging. `keys (T) @ <[pattern]> after <[key]>` walks the pattern's keys that come after `key`, and `from <[key]>` starts at `key` itself. The bound is a whole key of the pattern's shape (`desc` members included; anything else is a compile error naming both types), binds tighter than `take`, `if`, `reverse_of` and `sorted_by`, and compiles to the engine's range cursor, so the walk seeks to the bound: page k costs what page 1 does, where `skip` reads and discards every row before the page and a deep `skip` page is refused by the per-read budget. **`after` is now a reserved word**; a package that names something `after` must rename it (no `.orly` file in this repository did). A paging method returns its rows and the last key, and the caller passes that back: the TypeScript and Python clients' `pages` and the Go client's `Pages` do this until an empty page, sending integral cursor values back as ints. Each page reads the data as it is when it runs. A private POV with no writes is no snapshot: each page sees its parent as the parent sees itself then, its unpromoted writes included, and other POVs' writes once promoted to an ancestor (a delete of a key an ancestor holds is the exception until it is promoted, #791); see [paging through keys](docs/walkthrough.md#paging-through-keys). Also fixed on the way: the memory layer's range walker scanned the layer from its head instead of seeking through the skip list, and found nothing unless its start key was stored; the memory and disk range walkers take a pattern as the end of the range (the bound walks to the end of the pattern's matches), and pooled disk walkers no longer carry a previous walk's position or history into the next. Diagnostics-pin lang_tests (`diag_*.orly`) now pass when orlyc refuses them with their pinned message instead of being listed as expected failures (#735).
