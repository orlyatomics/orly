- **Changed (performance)**: Reading a note no longer takes the page-cache slot lock a second time. A note pin is now taken from the page the stream already holds, with an atomic increment, and only the last release of a page takes the lock. The slot spin also pauses between attempts and yields the CPU after a long wait. With 64 concurrent sessions on a RAM-backed store, server CPU per read fell by about 14% on integer range queries (4.0 to 3.4 ms) and about 12% on a mixed read load (1.8 to 1.6 ms), and mixed throughput rose from about 4.2k to 5.1k reads per second. Single-session point reads and uuid-expand reads are unchanged.
