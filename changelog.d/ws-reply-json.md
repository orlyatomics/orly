- **Changed (performance)**: WebSocket replies are formatted about twice as fast. A method result's JSON is built straight from the result's state (ints, bools, reals, ids, strings, optionals, lists and addresses; anything else takes the old var path for that part), the reply text is written into the reply buffer without an ostream, and ids are formatted and copied without a libuuid call. The text is byte-for-byte what it was. On a 1000-row read the server's cost per returned row drops from about 6.2 µs to 3.2 µs, which halves `range_int`/`page_k` latency (p50 5.2 ms to 2.5 ms) and brings every M1 range shape's p99 under 10 ms on a 4-layer store.
