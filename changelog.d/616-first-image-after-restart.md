- **Fixed**: the first base image the file service wrote after a restart went over the image the file map had just been loaded from. The append log then started right after that image, so a crash during the write left no image the log could be replayed onto, and the next start failed with "File System is corrupt". After a restart, the next base image now goes to the other image, as it does while running, so the loaded image plus the log can still stand in for it. A related recovery path is fixed too: when the very first base image a file system wrote is cut short, startup used to keep the part of the map that image's first block held and skip replaying the log, silently losing every file in the rest of it; it now replays the whole log (#616).
