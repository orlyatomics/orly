- **Fixed**: a durable layer's "marked for delete" flag was a plain `bool` that the durable writer and merger set under the mapping lock, while a view read it on every release of its memory layer without that lock, so ThreadSanitizer reported a race in the `orlyi` smoke. It is now atomic, and only the release that drops the last reference reads it. That release always comes after the mark, because the mapping being replaced still holds a reference when the layer is marked and gives it up only under the mapping lock, so no marked layer was ever left unqueued. A new `durable_manager.test` case parks the writer between writing a layer and marking it, reproduces the race, and checks that each layer is queued for removal exactly when its last reference goes (#727).
