- **Fixed (undefined behavior, found by a UBSan build)**: `TCore` is a packed 24-byte cell that sits at arbitrary byte offsets in notes, but `TCore::ForceAs<T>()` and everything built on it handed out a `const T &` (or `const T *`) into the cell, which is a misaligned reference for any scalar wider than a byte. Reads now go through a new `Base::ReadUnaligned<T>` (a fixed-size `memcpy`, which compiles to the same single load) and return the value: `ForceAs<T>()`, `State::TScalar::Get()` and its implementers return by value, and `TryGetOffset()` / `TryGetElemCount()` return `std::optional`. The in-memory cell layout, the on-disk format and the persisted quick hash are unchanged; `kit2.test` now pins the cell bytes and the quick hash of each integer width (#993). This is a public sabot API change: `State::TScalar<...>::Get()` is now `virtual TVal Get() const` rather than `const TVal &Get() const`, so an out-of-tree `State` implementer must change its override's return type, and a caller that took the address of the result or bound a non-const reference to it must copy it first. No such implementer or caller exists elsewhere in this repository (clients/, bench/, docs/ and examples/ were checked).
