- **Fixed**: once a package's records had been read, installing another package that declares the same record type, or the next version of the same package, crashed `orlyi` on the next read of those records, so upgrading a live package took the server down. Every package registered its record fields in static members of `Orly::Native::Record<T>`, and since a generated record class is named only after its fields, two packages declaring the same type instantiate the same `Record<T>`. g++ emitted those members as `STB_GNU_UNIQUE`, which the dynamic linker binds to one copy across every `dlopen()`'d package, so the second package added its fields to the first package's list after that list's array was sized, and the next read ran off the end of the array. The registry now has hidden visibility, so each package keeps its own. Stored data is unaffected: records written by a package built with an older `orlyc` read back correctly through the same package recompiled with this one. **Packages compiled by an older `orlyc` still share their registries with each other**, so the server now refuses to load such a package when an already loaded one, also built by an older `orlyc`, declares the same record type, and reports which type collided instead of crashing later. Recompile packages with this release's `orlyc`. A new smoke (`clients/smoke/run-package-upgrade.sh`) and a new `tests/restart_test.sh` cycle upgrade a package that holds records, on a live server and across a restart, and `manager.test` checks that compiled packages export no shared registry and that the loader refuses a colliding older-orlyc package (#797).
