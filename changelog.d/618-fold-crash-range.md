- **Fixed**: a crash at the end of a disk merge could make `+=` values count twice after a restart (#618). When a merge folds `+=` chains, its output recorded only the sequence range of the updates the fold kept. If the server stopped after the output reached the file map and before the merge's inputs were removed, the reload could keep an input next to the output, and every key they shared read its deltas twice; a debug build stopped on the mapping assertion instead. The output now records its inputs' whole range, as the plain merge path has since #592, so the reload recognises and drops every leftover input. The reload also drops an older file that overlaps a newer one, which covers most leftovers of a fold merge written by earlier versions. The fault-injection harness's reopen check never compared any values, because the keys it read were only known to the process that wrote them. It now reads the keys from the run's record.
