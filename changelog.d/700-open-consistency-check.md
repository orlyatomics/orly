- **Added**: a reopened disk store is checked for consistency at open, in every build ([#700](https://github.com/orlyatomics/orly/issues/700)). Every block the volumes hold must belong to exactly one owner (the system block, a base image, the append log, or a data or durable file in the file map), and each repo's data files must cover disjoint sequence ranges. Leaked blocks (#620's class) and overlapping or inverted ranges are logged at `LOG_ERR`; a block a live file owns that is free or waiting for discard (#610's class), or a block owned twice, refuses the open, because the next file allocated could be written over live data. `--open_check=false` skips the check, for recovering such a store. Reloading a repo now also logs each merge leftover it drops, and checks in release builds that what remains is strictly monotone (until now a debug-only assert). One summary line (`open check: N files, ...`) is logged at `LOG_INFO` on a clean store; the check reads each file's block list once and scans the block map once.
