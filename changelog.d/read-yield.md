- **Changed (performance)**: A point read no longer waits behind a long scan on the same fast runner ([#1015](https://github.com/orlyatomics/orly/issues/1015)). Every 16 rows (`--read_yield_rows`), a method call checks whether another statement is waiting on its runner and yields to it if so; a call whose sequences yield many elements without reading rows checks at the same pace, counting 64 elements as one row. A read also counts toward its runner's load as it walks, one small statement's worth per 32 rows, so new statements steer around a runner that is busy with a scan. `--read_yield_rows=0` turns both off.
