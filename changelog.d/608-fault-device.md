- **Added**: a fault-injecting test device and a harness that uses it (#608). `Sim::TFaultDevice` (test-only, `orly/indy/disk/sim/fault_device.h`) can fail the Nth read, write or sync the way a real device does, or lose power at the Nth sync: writes since a device's last completed sync are lost, or optionally torn at sector granularity. `Sim::TFaultEngine` runs the real file service on these devices, so a new engine can be opened over the image a power loss leaves. `orly/indy/fault_injection.test` loops N over a memory merge, a disk merge on both the plain and the fold path, a durable save with the durable merge, and a file-service base image. Each run happens in a child process, so an `abort()` or a hang ends only that run. A run must finish without hanging or leaking blocks, and after a power loss the engine must reopen with every acknowledged write intact. It found #618 (fold-path merge overlaps its input after a crash), #619 (durable files are not synced before they enter the file map), #620 (reload leaks the blocks of leftover merge inputs) and #621 (an fsync error kills the file service and hangs every later file-map change). All four are pinned as expected failures until they are fixed.
