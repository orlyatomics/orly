- **Fixed**: pausing or unpausing a POV with no unpromoted writes on a master with a live slave aborted a debug master (`PushTransaction`: `mutation.GetSequenceNumber()`), and in release sent the slave an indeterminate sequence number that the slave then compared against its own empty one (#655). The common "pause, then write" order hit it, because the POV is empty when the pause commits. Such a status change now travels with sequence number 0, which no update ever has, and the slave applies it only if its copy of the POV is empty too. The slave logs each replicated pause, unpause and fail it applies or discards.
