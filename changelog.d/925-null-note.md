- **Fixed**: a release `orlyi` could crash with SIGSEGV on a read when the page cache ran dry. A note that straddles a cache page is copied out of the page cache, and if that read failed (`Ran out of cache pages`, or a disk error) `TDiskArena::TryAcquireNote` swallowed the error and returned a null note; the pin check that would have caught it only existed in debug builds, so a release build went on to dereference it. The read now fails with the real error and the session gets it back, and the pin check is unconditional ([#925](https://github.com/orlyatomics/orly/issues/925)).
