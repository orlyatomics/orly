- **Changed (performance)**: A disk merge now takes a run of up to eight adjacent files, each in the same or a higher generation than the one before it, instead of only a pair. A backlog of small files used to drain one file per merge, rewriting each generation's data about three times on its way to the next. On the M1 harness's post-ingest store (412 disk files), merges now settle at 30 files in 23 minutes, writing 25.7 GB; before, they were still at 107 files when the 30-minute settle timed out, having written 36.3 GB. Since a merge drops an input's superseded history but keeps its current versions, a version that a run merge carries is dropped at the next merge it is in, so up to eight files' worth of overwritten versions can stay on disk one merge longer than before. A merge of more inputs also holds more working memory while it runs.
