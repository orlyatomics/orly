- **Changed**: the per-read budget is charged while a method runs, not only on rows read and the final result. Values a call builds without reading rows (`[0..n] as [int]`, strings grown in a `reduce`, joined lists, sets and dicts) count against `--read_budget_mb` as they grow, and each element a sequence yields is a step against the new `--read_budget_steps` (default: one per byte of `--read_budget_mb`), so a loop that reads and builds nothing is refused too. A list or loop whose length is known up front is refused before it starts. The refusal is still `read_too_large`, and its message says which limit was passed. `[0..30000000] as [int]` under a 16 MiB budget used to grow `orlyi` by about 1.6 GB before it was refused; it is now refused before it starts. `--read_budget_mb=0` still turns the whole budget off ([#729](https://github.com/orlyatomics/orly/issues/729)).
