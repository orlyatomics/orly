- **Fixed**: `orlyi`'s crash handler printed nothing on a real crash. It walked the stack before writing anything, so the first `backtrace()` (which loads `libgcc_s` and allocates) could fault inside the handler and kill the process silently; and it was installed with `signal()` and no alternate stack, so it ran on the faulting thread's own (fiber) stack. The handler now writes `*** CRASH SIGNAL RECEIVED ***` first, warms `backtrace()` at startup, is installed with `sigaction` and `SA_ONSTACK`, and every scheduler worker and fiber runner thread gets an alternate signal stack. A test forks a child that faults (null write, on another thread, stack overflow) and checks the message comes out.
