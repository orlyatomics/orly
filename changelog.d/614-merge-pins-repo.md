- **Fixed**: a memory merge could run on a repo that had already been destroyed (#614). The merge runner took a raw pointer off its queue and held no pin, so when a closed ttl=0 pov's last pin, its dirty self-pin, dropped on another thread mid-merge, the repo and its layers were freed under the merge. Debug builds died on `StepMergeMem`'s `iter != update_remap.end()` assertion or segfaulted; release builds read freed memory. A repo queued for a memory merge now holds a pin, which the runner keeps until the merge returns, and the dirty self-pin is only ever reset under `DataLock` and released after it. On native arm64 runners, `import_replication.test`'s `PrunedJoinWithoutFileSync` crashed its master 9 times in 232 runs before the fix and 0 times in 980 runs after.
