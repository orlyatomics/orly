- **Fixed**: `orlyi` now runs under ThreadSanitizer in CI, and the races and lock-order inversions that first run found are fixed. A memory layer's "taken" flag was a plain `bool` that merges set while views and mappings read it on other threads. It is now atomic, and only the release that drops the last reference reads it. That release was always ordered after the merge, so no layer leaked; a new `repo.test` case drives the race and checks that every merged layer is freed. A session added a POV by copying its durable pointer under the session's POV lock, while closing a session takes that lock under the durable manager's lock. The copy now happens outside the lock, and `Durable::TPtr`'s moves are `noexcept`, so a growing POV list no longer copies pointers under it. The reporting port read the durable pools' block counts and each volume's used-block count without the writers' locks; those reads are now atomic or locked. The TSan job builds `orlyi` and `orlyc` and runs the memory-drain smoke against them (`clients/smoke/run-tsan-server.sh`), with a negative control. One known inversion, between a child repo's data lock and the Tetris player's mutex, is suppressed in `orly/tsan.supp` until #660 removes it (#713).
