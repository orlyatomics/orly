- **Fixed**: a page prefetch whose read fails no longer hangs the reader. The page cache's two async loaders registered each read on the stream's completion trigger but completed it only on success. So when a read failed, the fiber destroying the stream waited forever. The multi-page loader also left a failed page looking as if it was still loading, so any later read of it spun forever instead of failing. Both loaders now complete the trigger on failure, and both mark a failed page as loaded with an error, so a read of it throws. A stream's destructor no longer throws when one of its prefetches failed, which would have terminated the process. It logs the failure instead, because a reader of that page gets the error from the page itself. Nothing hit this in a test or a run: the cache's reads abort on a checksum failure before reporting it, so only a device I/O error or a failed submit reaches this path (#596).
