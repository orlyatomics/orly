- **Fixed**: `sorted_by` now keeps ties in their input order, and a comparator like `lhs <= rhs` can no longer crash it. It used `std::sort`, which leaves the order of equal elements unspecified, so results could differ between builds. With a comparator that isn't a strict ordering, `std::sort` is undefined behaviour: sorting 1,000 equal values with `<=` read past the end of the vector under AddressSanitizer, and segfaulted in a debug build. It now uses `std::stable_sort`. A comparator that holds for an element against itself (`<=`, `>=`, or one that is always true) is sorted by its strict part instead, so `<=` gives exactly the order `<` does; that check costs one call per sort, and the strict part a second call per comparison only for such comparators (#698).
