- **Fixed**: a long run of disk merges could end with `orlyi` terminating on `Bad Alloc in TThreadLocalPool [TDiskController::TEvent]` while almost every disk event was free. A thread-local pool takes its whole free queue for itself on its next allocation, where no other thread can steal from, so each merge thread kept the most events it had ever used at once. In one measured run 235 of 8221 events were in use and 7984 sat free in other threads' pools. A pool now keeps at most a 256th of the objects (at least 16) and hands the rest back to the shared list, and a pool that goes away hands back what it holds. The `bad_alloc` that remained then terminated the process instead of reaching the disk merge's recovery: `~TOutStream` wrote out its buffered blocks while the stream's owner was unwinding, which needed more disk events and threw from a destructor. It now frees those buffers instead, since the write is being abandoned. A flush that fails part way also no longer leaves the stream holding buffers that the failed writes' callbacks had already freed.
