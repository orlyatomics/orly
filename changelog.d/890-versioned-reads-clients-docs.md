- **Added (clients, docs)**: versioned reads in the clients (#890, #745). The TypeScript, Python and Go drivers take an `at` option on `call` (a version, `{time}` or `{save}`), expose every reply's `version` (`lastVersion` / `last_version` / `LastVersion`), add `versionOf`, `hold`/`release` and `savePoint`/`dropSavePoint`, and pin `pages()` to the first page's version so a listing is one consistent read. `version_unavailable` is a typed error (`VersionUnavailableError`) and is never retried. The MCP `orly_call` tool takes `at`. `docs/PROTOCOL.md` and `docs/architecture.md` describe the statements, the retention flags and `version_unavailable`, including the upgrade note: a binary from before #846 (such as v0.2.0) has no store-format check and would open a format-2 store. `examples/grc20-pov` gains `versioned.orly` and `versioned_demo.py`, answering "what did this say last week, and what changed since" with native reads instead of user-space event folding. One engine fix, found by running a read at a version against a live disk-backed `orlyi`: `$at` is no longer read from a dead temporary (it arrived as a garbage number). The Go driver also reads versions the server prints as `4.000000`.
