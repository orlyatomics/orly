- **Fixed**: a slave no longer applies replicated mutations to an empty stand-in for a pov's repo it has already discarded. Nothing on a slave pins its copy of a pov's repo, so a copy with no ttl goes as soon as the slave builds it, and the cache can let any other go. The slave opened the gone repo by force for each mutation, which builds an empty repo whose sequence starts at 1: with no repo cache, the second write to a pov failed the slave's sequence check (an assert in debug builds, "missing data" in release). A pov created under a parent the slave had discarded likewise got an empty stand-in as its parent, and after a failover it read nothing through it. The slave now skips a mutation for a gone repo, and doesn't create a pov whose parent has gone, so after a failover that pov is refused like any other the new master lacks (#671).
